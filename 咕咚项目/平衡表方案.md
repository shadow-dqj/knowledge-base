**咕咚加油线上平衡表日汇总方案**

范围：每日汇总充值、消费、优惠、剩余余额和平衡差额；支持任务失败后按已成功处理位置继续执行

|           |                                                 |
| --------- | ----------------------------------------------- |
| **审核结论项** | **方案口径**                                        |
| 建设目标      | 每天凌晨生成上一业务日的线上会员资金汇总，页面支持按日期查询。                 |
| 统计内容      | 充值、消费、优惠、剩余余额、平衡差额。                             |
| 展示层级      | 公司总汇总、会员类别汇总、会员类别+站点汇总，第三层可穿透订单明细。              |
| 新增表       | 保留一张汇总结果表，新增一张简化任务执行表。任务表用于记录任务状态、失败原因和已成功处理位置。 |
| 续跑要求      | 任务失败后不从头处理，根据 last_success_id 从下一条主数据继续执行。      |

# **二****、数据表设计**

需要新增两类表：一张日汇总结果表，一张任务执行表。汇总结果表用于页面展示，任务执行表用于记录任务状态和续跑位置。

|   |   |   |
|---|---|---|
|**表名**|**用途**|**说明**|
|r_member_finance_day|会员资金日汇总结果表|保存三层汇总结果、金额指标和平衡差额。|
|r_member_finance_day_task|会员资金日汇总任务表|保存业务日期、任务状态、开始/结束时间、已成功处理位置和异常内容。|

会员资金日汇总结果表结构如下：

CREATE TABLE r_member_finance_day (

  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',

  billdate DATE NOT NULL COMMENT '业务日期',

  memberlevel VARCHAR(32) NOT NULL DEFAULT '' COMMENT '会员类别编码',

  membername VARCHAR(64) NOT NULL DEFAULT '' COMMENT '会员类别名称',

  stationid VARCHAR(32) NOT NULL DEFAULT '' COMMENT '站点ID',

  stationname VARCHAR(100) NOT NULL DEFAULT '' COMMENT '站点名称',

  reamount DECIMAL(18,2) NOT NULL DEFAULT 0.00 COMMENT '充值金额',

ysamount DECIMAL(18,2) NOT NULL DEFAULT 0.00 COMMENT '充值应送金额',

  ssamount DECIMAL(18,2) NOT NULL DEFAULT 0.00 COMMENT '充值实送金额',

  xfamount DECIMAL(18,2) NOT NULL DEFAULT 0.00 COMMENT '消费金额',

  skamount DECIMAL(18,2) NOT NULL DEFAULT 0.00 COMMENT '实扣金额',

  dnamount DECIMAL(18,2) NOT NULL DEFAULT 0.00 COMMENT '优惠金额',

  endbalance DECIMAL(18,2) NOT NULL DEFAULT 0.00 COMMENT '余额',

  createtime DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',

  updatetime DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',

  PRIMARY KEY (id),

  UNIQUE KEY uk_bill_level_member_station (billdate, rptlevel, memberlevel, stationid),

  KEY idx_bill_level (billdate, rptlevel),

  KEY idx_bill_member_station (billdate, memberlevel, stationid)

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='会员资金日汇总结果表';

任务执行表结构如下：

CREATE TABLE r_member_finance_day_task (

  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',

  billdate DATE NOT NULL COMMENT '业务日期',

  status TINYINT NOT NULL DEFAULT 0 COMMENT '状态：0待执行，1执行中，2成功，3失败',

  starttime DATETIME DEFAULT NULL COMMENT '任务开始时间',

  endtime DATETIME DEFAULT NULL COMMENT '任务结束时间',

  last_success_id BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '已成功处理到的最后一条主数据ID',

  errormsg VARCHAR(1000) NOT NULL DEFAULT '' COMMENT '异常内容',

  createtime DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',

  updatetime DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',

  PRIMARY KEY (id),

  UNIQUE KEY uk_billdate (billdate),

  KEY idx_status_time (status, updatetime)

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='会员资金日汇总任务表';

# **三****、汇总任务与失败续跑机制**

任务每天凌晨 1 点执行，默认处理 T-1 业务日期；也支持手动传入 billdate 重跑指定日期。

|   |   |
|---|---|
|**处理节点**|**处理规则**|
|任务创建|按 billdate 查询任务表；不存在则新增任务记录，status=1。|
|数据处理|按主数据 ID 升序分批处理，每批成功后更新 last_success_id 和 updatetime。|
|任务失败|记录 status=3、errormsg、endtime，last_success_id 保留最后成功位置。|
|再次执行|读取 last_success_id，从 id > last_success_id 的下一条主数据继续。|
|任务成功|全部处理完成后写入或更新汇总结果，status=2，记录 endtime。|

示例：某日任务共 10000 条主数据，已成功处理到 6000 后失败，则任务表 last_success_id=6000。下次执行同一业务日期任务时，从 id > 6000 开始处理，前 6000 条不重复执行。

为避免页面读取半成品数据，页面只展示已完成任务对应的汇总结果；失败中的任务仅用于续跑和排查。

# **五****、验收标准与工期预估**

· 不输入日期时默认展示 T-1 日汇总。

· 每天凌晨 1 点可自动生成上一业务日汇总。

· 同一业务日期任务重复执行时，不产生重复任务记录。

· 任务失败后保留 last_success_id，再次执行可从下一条主数据继续。

· 三层汇总和订单明细可正常查询，差额颜色按规则展示。

· 充值、消费、优惠、剩余余额可与来源表抽样核对一致。
