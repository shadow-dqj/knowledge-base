# 会员充值消费平衡表功能说明

> [!info] 文档定位
> 本文说明“会员充值消费平衡表”当前已经实现的功能、业务口径、操作方式、权限要求、任务机制和手工验收方法，供业务验收、测试和部署运维使用。技术设计和历史决策参见[[平衡表方案]]。

## 一、功能概述

会员充值消费平衡表是一套旁路只读统计功能，用于：

- 查询会员真实加油原价、优惠前结算、客户实际支付和优惠金额。
- 分别核对汽油、柴油、非油品账户的期初、期间流水、计算期末、实际期末和平衡差额。
- 按公司、会员类别、站点逐层查看汇总，并钻取充值、退款、余额扣款和加油明细。
- 记录每日汇总任务状态及数据质量诊断结果。
- 支持对昨天及以前的单个业务日进行手动重算。

报表只读取业务数据，只写 `r_member_finance_day` 和 `r_member_finance_day_task`，不修改充值、加油、退款、优惠计算或账户余额。

## 二、菜单与权限

| 项目 | 内容 |
| --- | --- |
| 菜单名称 | 会员充值消费平衡表 |
| 菜单编号 | `803027` |
| 上级菜单 | `8030` |
| 菜单位置 | 数据分析 -> 财务分析 |
| 页面地址 | `page/comReportQuery/memberFinanceDay.html` |
| 权限接口 | `/com/rpt/ComMemberFinanceDayTree` |

菜单脚本只新增菜单，不自动复制其他菜单的角色权限，需要在现有角色权限页面手动授权。

> [!warning] 授权后需要重新登录
> 角色权限保存成功后，系统会清除该角色用户的 Redis 登录和菜单缓存。随后出现“签名失败”不代表保存失败，退出并重新登录即可。

“签名失败”和“会员充值消费平衡表执行失败”是两个不同问题：

- 签名失败：登录缓存因角色权限变更失效，重新登录处理。
- 平衡表执行失败：报表接口、数据库结构或汇总任务异常，检查任务记录和服务日志。

## 三、页面功能

### 3.1 主页面

主页面默认查询 T-1，包括：

- 业务日期、查询和手动重算。
- 任务状态与诊断信息。
- 公司级总览卡片。
- 会员类别和站点树。
- 会员类别或站点汇总表。
- 经营指标、汽油账户、柴油账户、非油品账户四种视图。

### 3.2 经营指标

| 指标 | 含义 |
| --- | --- |
| 加油原价 | 按油价和数量形成的原始金额 |
| 优惠前结算 | 优惠分摊前的结算金额 |
| 客户实际支付 | 客户最终实际承担金额 |
| 优惠总额 | 客户实际享受的优惠金额 |
| 价格差异 | 加油原价减优惠前结算，不计入优惠 |
| 优惠拆分差额 | 优惠总额减各项优惠组成 |
| 发券数量/券面值 | 充值订单实际关联发放的优惠券 |

### 3.3 三账户勾稽

汽油、柴油、非油品账户分别展示：

- 期初余额。
- 充值本金。
- 现金实送。
- 退款冲减。
- 余额消费扣款。
- 计算期末。
- 实际期末。
- 平衡差额。

### 3.4 会员类别和站点

- 公司层：经营指标及三账户权威余额勾稽。
- 会员类别层：按会员当前等级归类，用于定位差异。
- 站点层：只展示本站业务流水，不计算站点余额。

站点层不计算余额，是因为现有 `s_account.stationid` 没有可靠的余额归属数据。

### 3.5 明细

当前明细包括普通充值、退款、余额消费实际扣款和加油订单。

加油明细以 `s_consorder` 为主表左连接 `r_consorderlist`，展示加油原价、优惠前结算、客户实际支付、优惠总额、价格差异、各项优惠组成、拆分差额和宽表匹配状态。宽表缺失时仍显示订单主金额，并明确标记组成缺失。

> [!note] 当前未实现
> 尚未实现手机号、昵称、订单号和 `userid` 的统一个人筛选，也未实现四类流水间保持同一客户筛选条件。

## 四、业务口径

### 4.1 加油金额

```text
优惠前结算金额 = 客户实际支付 + 优惠总额
s_consorder.sumamount = s_consorder.payamount + s_consorder.dnamount
```

| 指标 | 权威字段 |
| --- | --- |
| 加油原价 | `s_consorder.ysumamount` |
| 优惠前结算 | `s_consorder.sumamount` |
| 客户实际支付 | `s_consorder.payamount` |
| 优惠总额 | `s_consorder.dnamount` |
| 价格差异 | `ysumamount - sumamount` |

优惠组成：

```text
rechargmoney + usermoney + memberamount + netcaramount
+ activityamount + couponamount + accpointsamount
```

```text
优惠拆分差额 = 优惠总额 - 优惠组成
```

价格差异不是优惠，也不是会员余额扣减。

### 4.2 充值与权益

- 普通充值本金采用 `s_rechargeorder.reamount`。
- 现金实送采用订单实际落库的 `s_rechargeorder.dnamount`。
- `s_rechargemedium` 是会员来源或推广渠道限制，不是实物赠品。
- 水等实物权益通过实际发放优惠券表达，按 `s_couponuser.moduleid = s_rechargeorder.orderid` 关联。
- 充值活动油惠在消费时发生，按 `r_consorderlist.rechargmoney` 统计。

### 4.3 权威余额流水

| `ordertype` | 业务 | 账户方向 | 金额 |
| --- | --- | --- | --- |
| `0` | 普通充值 | 增加 | `reamount + dnamount` |
| `1` | 余额消费 | 减少 | `sumamount` |
| `3` | 退款 | 减少 | `sumamount` |

成功退款以正数保存，因此在余额公式中作为减项。微信等外部支付没有 `ordertype='1'` 流水，不影响会员余额。

### 4.4 账户类型

| `activityrtype` | 账户 | 当前余额字段 |
| --- | --- | --- |
| `1` | 汽油 | `s_account.banlance` |
| `2` | 柴油 | `s_account.cybanlance` |
| `8` | 非油品 | `s_account.tybanlance` |

### 4.5 余额公式

```text
计算期末
= 期初余额
+ 普通充值本金
+ 现金实送
- 退款本金及赠送冲减
- 余额消费实际扣款

平衡差额 = 计算期末 - 实际期末余额
```

差额判断阈值统一为 `0.01` 元。

## 五、汇总任务

### 5.1 报表专用表

| 表 | 用途 |
| --- | --- |
| `r_member_finance_day` | 每日经营指标和账户勾稽结果 |
| `r_member_finance_day_task` | 单日任务状态、步骤、错误和诊断统计 |

`accounttype='0'` 表示经营指标，`1/2/8` 分别表示汽油、柴油和非油品账户。

### 5.2 任务状态

| `isstate` | 状态 |
| --- | --- |
| `0` | 待执行 |
| `1` | 执行中 |
| `2` | 执行失败 |
| `3` | 执行成功 |
| `4` | 已取消 |

失败时查看 `stepname`、`lasttable`、`errmsg` 和 `alarmmsg`。

### 5.3 一致性保护

- PostgreSQL advisory lock 防止同公司同业务日并发重算。
- `RepeatableRead` 快照保证源数据读取时点一致。
- 成功时单事务整日替换汇总结果。
- 失败时回滚并保留上一版完整结果。
- 报表任务失败不影响正常充值、加油、退款和账户业务。

### 5.4 数据质量诊断

包括余额消费缺流水、孤立余额流水、消费宽表缺失、未识别会员、未归属站点、未知账户类型及差额检查。诊断只告警，不自动修改业务数据。

## 六、接口

| 接口 | 功能 |
| --- | --- |
| `POST /com/rpt/ComMemberFinanceDayOverview` | 公司经营指标和三账户勾稽 |
| `POST /com/rpt/ComMemberFinanceDayTree` | 会员类别和站点树 |
| `POST /com/rpt/ComMemberFinanceDayMember` | 会员类别下各站汇总 |
| `POST /com/rpt/ComMemberFinanceDayStation` | 指定会员类别和站点汇总 |
| `POST /com/rpt/ComMemberFinanceDayRecharge` | 充值、退款、余额扣款明细 |
| `POST /com/rpt/ComMemberFinanceDayCons` | 加油订单明细 |
| `POST /com/rpt/ComMemberFinanceDayTask` | 单日任务状态和诊断 |
| `POST /com/rpt/ComMemberFinanceDayRebuild` | 当前公司单日手动重算 |
| `POST /job/ComJobMemberFinanceDay` | 定时签名任务入口 |

限制：汇总最多查询 366 天，明细最多 31 天，单页最多 200 条，手动重算只允许昨天及以前的单日。

## 七、部署与使用顺序

1. 执行 `bjos.maninterface.recon/database/r_member_finance_day.sql`。
2. 部署当前后端和前端。
3. 执行 `r_member_finance_day_menu.sql` 新增菜单 `803027`。
4. 在角色权限页面授予菜单。
5. 重新登录，刷新 Redis 权限缓存。
6. 选择昨天或更早日期执行一次手动重算。
7. 任务成功后查询报表。
8. 配置每日 T-1 定时任务。

## 九、常见问题

### 授权成功后“签名失败”

角色权限保存后 Redis 登录缓存失效。重新登录即可，无需重复授权。

### “会员充值消费平衡表执行失败”

1. 确认已执行最新 `r_member_finance_day.sql`。
2. 在浏览器网络中定位任务、总览或树接口。
3. 查询任务表的 `errmsg`、`stepname`、`lasttable`。
4. 查看服务日志中的 `member finance report error:` 或 `member finance day rebuild error:`。
5. 修复后重新执行该业务日，不修改正常业务流水。

### 日期尚未生成日汇总

对所选日期执行手动重算，任务成功后重新查询。

### 站点为什么没有余额

现有账户数据没有可靠站点归属，因此站点层只展示流水。
