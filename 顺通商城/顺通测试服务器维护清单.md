- 四台处于同一内网网段（`192.168.1.0/24`），通过外网入口 `124.128.84.22` 的不同 SSH 端口接入。
- **端口 ↔ 主机对应关系由 SSH 主机密钥指纹比对确认**（从已连通主机 `ssh-keyscan` 取指纹后与 `192.168.1.250` ~ `.253` 逐一比对），不是按端口号推测：`60123` → `.252`、`60124` → `.253`、`60125` → `.250`、`60126` → `.251`。
- 另有一个 `60122` 端口开放，但其主机密钥指纹与这四台均不匹配，身份未确认，暂未登记。
- 商城测试1 还带 Docker 网桥地址 `172.17.0.1 / 172.18.0.1 / 172.19.0.1`；商城测试2 另有 `192.168.6.249`（`enp2s0`，NO-CARRIER）；商城测试3 / 商城测试4 的网卡信息待补。
- 部署配置：`192.168.1.253:/data/java/docker-compose.yml`（YAML 锚点 + `network_mode: host`）+ `start-service.sh`（单服务启动脚本）；四台主机在 compose 中以 `mall4test-250` ~ `mall4test-253` 作为 `extra_hosts` 别名。
- **SSH 凭据状态**：维护公钥 `factory_server_maintenance_ed25519` 已在四台服务器侧生效，四台均可直接登录（`60123` → `mall4test-252`、`60124` → `didaima`、`60125` → `mall4test-250`、`60126` → `mall4test-251`）。
- **`UseDNS` 已修复（2026-09-28）**：`192.168.1.250` / `.251` / `.252` 三台原本 `UseDNS yes`，登录前反向解析客户端 IP 要等约 20s，超过 Droid SSH MCP 固定 20s 的连接超时，经 MCP 会报 `SSH connection timeout`。已在三台置 `UseDNS no`（备份 `/etc/ssh/sshd_config.bak-20260928`）并 reload sshd，MCP 四个 profile 现已全部可用。

## 五、Nginx 部署

- 容器：`mall4cloud-nginx`，主机网络模式，监听 `80` / `443`。
- 挂载映射（宿主机 ↔ 容器）：
  - `/data/nginx/html` ↔ `/usr/share/nginx/html`（前端静态文件）
  - `/data/nginx/conf.d` ↔ `/etc/nginx/conf.d`（站点配置）

- 证书文件：`/data/nginx/ssl/sdstsh.cn.pem` + `/data/nginx/ssl/sdstsh.cn.key`（通配符 `*.sdstsh.cn`）。

### 2026-09-28 部署扩容：2 台 → 4 台

- 新增 `192.168.1.250` / `192.168.1.251` 两台，SSH 入口 `root@124.128.84.22:60125` / `:60126`；后端服务重新分配为 1 / 5 / 5 / 5。
- 端口与主机的对应关系改用 SSH 主机密钥指纹比对确认（60123→`.252`、60124→`.253`、60125→`.250`、60126→`.251`）；`60122` 开放但指纹不匹配，身份待确认。
- 服务分布改为以 Nacos 实例列表实测为准，取代原「测试1 承载 6 个 / 测试2 承载 10 个」的旧拆分。
- Droid SSH MCP 配置新增 `商城测试3` / `商城测试4` 两个 profile。
- 服务器侧加入维护公钥后四台均可直接登录，主机名确认 `mall4test-250` / `mall4test-251` / `mall4test-252` / `didaima`。
- 定位 `商城测试1` / `3` / `4` 经 SSH MCP 报 `SSH connection timeout` 的根因：三台 `UseDNS yes` 导致认证前反向解析约 20.6s，超过 ssh-mcp 硬编码的 20s 连接超时；`.253` 为 `usedns no` 故正常。
- 修复上述超时：三台（`.252` / `.250` / `.251`）`sshd_config` 置 `UseDNS no`（备份 `/etc/ssh/sshd_config.bak-20260928`）并 `systemctl reload sshd`；`商城测试1` / `3` / `4` 经 MCP 复测全部通过（分别返回 `mall4test-252` / `mall4test-250` / `mall4test-251`）。
- 遗留：商城测试3 / 4 的网卡信息待补。

### 2026-09-10 Nginx 审计与修复

- 修复历史遗留 `cloud-*.conf` 的容器内无效 `root /data/nginx/html/...` 路径，统一改为 `/usr/share/nginx/html/...`。

### 2026-09-10 证书替换

- 原证书仅覆盖主域名 `sdstsh.cn / www.sdstsh.cn`，子域名访问报 `ERR_CERT_COMMON_NAME_INVALID`。
- 已替换为通配符证书 `*.sdstsh.cn`（DigiCert RapidSSL），reload 后经 `openssl s_client` 验证 SAN 含 `*.sdstsh.cn`。

### 2026-09-10 H5 基础路径 MIME 修复

- 根因：uni-app 打包资源使用绝对前缀，而站点曾把 `root` 指到子目录，导致 `/h5/assets/...` 实际解析到 `/h5/h5/assets/...`，404 后回退 `index.html`（`text/html`）。
- 修复：`cloud-shop-h5.conf`、`cloud-ms.conf` 改为前缀挂载（`/h5`、`/multishop-h5`）+ 根路径 301；`cloud-h5.conf` 同步为 `/h5` 挂载。
- 验证：`h5test`、`shop-h5test`、`multishop-h5test` 的 JS 资源均返回 `application/javascript`，`nginx -t` 通过。
- 备份：`cloud-shop-h5.conf.bak-20260910_175833`、`cloud-ms.conf.bak-20260910_175833`。
