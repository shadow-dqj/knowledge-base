# 商城余额与燃油充值账务设计对比

## 结论

商城余额充值和汽油、柴油充值存在共同流程，但不应强行使用完全相同的账户和流水实现。

推荐原则：

> 业务规则统一，账户和账务表保持独立。

燃油充值当前采用独立订单、钱包和流水的设计，更适合汽油、柴油专用账户；商城余额继续沿用历史余额链路。

## 一、共同点

| 项目 | 共同逻辑 |
| --- | --- |
| 套餐来源 | 都使用 `user_recharge` 表 |
| 套餐区分 | 使用 `fuel_type`：0商城余额、1汽油、2柴油 |
| 业务场景 | 都按 `bizScene` 隔离零售和采购 |
| 金额单位 | 数据库存储为分 |
| 套餐排序 | 按 `seq` 排序 |
| 支付校验 | 校验金额及账户余额上限 |
| 支付配置 | 使用当前支付体系配置 |
| 幂等要求 | 支付成功只能入账一次 |

## 二、商城余额充值链路

### 账户

商城余额使用用户扩展账户，主要涉及 `user_extension` 的余额字段：

- `actual_balance`：实际可用余额；
- `balance`：余额总额或累计余额。

### 下单

接口：

```text
POST /mall4cloud_user/user_recharge/recharge
```

流程：

1. 接收套餐 ID 或自定义金额；
2. 查询 `fuel_type = 0` 的商城余额套餐；
3. 校验当前业务场景；
4. 创建 MongoDB 余额流水；
5. 以余额流水 ID 作为支付业务单号。

商城余额没有独立的关系型充值订单表，支付前主要创建 MongoDB `user_balance_log` 记录。

### 支付成功

支付成功后进入 `UserRechargeService.rechargeSuccess()`：

1. 更新 MongoDB 余额流水为已支付；
2. 增加商城余额；
3. 发放赠送余额；
4. 发放积分；
5. 发放成长值；
6. 发放优惠券。

商城余额套餐支持本金、赠送余额、积分、成长值和优惠券。

### 明细

主要存储在 MongoDB：

```text
user_balance_log
```

查询接口：

```text
GET /mall4cloud_user/user_balance_log/page
```

该流水还可能记录消费、退款、系统调整和其他余额变化。

## 三、汽油、柴油充值链路

### 账户

燃油账户使用独立表：

```text
user_fuel_wallet
```

通过 `(user_id, fuel_type)` 区分账户：

- `fuel_type = 1`：汽油；
- `fuel_type = 2`：柴油。

主要字段：

- `actual_balance`：当前可用燃油余额；
- `balance`：累计充值总额；
- `version`：乐观锁版本号。

### 套餐查询

```text
GET /mall4cloud_user/user_fuel_recharge/package_list?fuelType=1
GET /mall4cloud_user/user_fuel_recharge/package_list?fuelType=2
```

最终按以下条件查询：

```sql
where biz_scene = ?
  and fuel_type = ?
```

### 下单

接口：

```text
POST /mall4cloud_user/user_fuel_recharge/order
```

支付前写入关系型订单表：

```text
user_fuel_recharge_order
```

订单保存金额和支付配置快照，包括：

- 油品类型；
- 业务场景；
- 套餐 ID 和标题；
- 实付金额；
- 赠送金额；
- 应入账金额；
- 支付系统和供应商；
- 支付单号；
- 订单状态；
- 过期时间。

### 支付成功

支付成功后调用 `noticeRechargeSuccess()`：

1. 将燃油充值订单更新为已入账；
2. 创建或获取对应油品钱包；
3. 使用乐观锁更新汽油或柴油余额；
4. 写入充值本金流水；
5. 有赠送金额时，再写入套餐赠送流水。

燃油充值只支持充值本金、套餐赠送和退款流水，不发放商城积分、成长值或优惠券。

### 明细

燃油明细存储在 MySQL：

```text
user_fuel_wallet_log
```

查询接口：

```text
GET /mall4cloud_user/user_fuel_wallet/page_log?fuelType=1
GET /mall4cloud_user/user_fuel_wallet/page_log?fuelType=2
```

查询条件：

```sql
where user_id = ?
  and fuel_type = ?
order by create_time desc, fuel_wallet_log_id desc
```

汽油和柴油流水严格隔离。

有赠送的套餐通常产生两条流水：

```text
reason = 1：充值本金
reason = 2：套餐赠送
```

## 四、核心差异

| 对比项    | 商城余额                       | 汽油/柴油                        |
| ------ | -------------------------- | ---------------------------- |
| 账户表    | `user_extension`           | `user_fuel_wallet`           |
| 账户区分   | 普通商城余额                     | `fuel_type` 区分汽油、柴油          |
| 支付前记录  | MongoDB 余额流水               | MySQL 燃油充值订单                 |
| 独立充值订单 | 无独立关系型充值订单                 | `user_fuel_recharge_order`   |
| 充值明细   | MongoDB `user_balance_log` | MySQL `user_fuel_wallet_log` |
| 支付成功处理 | `rechargeSuccess()`        | `noticeRechargeSuccess()`    |
| 余额更新   | 用户余额服务                     | 燃油钱包乐观锁更新                    |
| 赠送权益   | 余额、积分、成长值、优惠券              | 仅燃油额度                        |
| 退款记录   | 商城余额流水类型                   | `reason = 3`，关联退款订单          |
| 油品隔离   | 不适用                        | 汽油、柴油分别隔离                    |

## 五、为什么不建议燃油完全照搬商城余额

商城余额属于历史链路：

```text
MongoDB user_balance_log
+ user_extension余额
+ 支付通知及消息处理
```

如果燃油也复用该模式，会带来以下问题：

- 汽油、柴油两个账户难以清晰隔离；
- 充值订单和账务流水不够直观；
- 余额变更与流水记录分散；
- 赠送金额、退款和冲正的对账复杂；
- 容易误增加商城余额或第三方用户资金账户；
- 不利于燃油账户后续消费、退款和审计。

燃油当前的“充值订单 + 专用钱包 + 不可变流水”更适合专用储值账户。

## 六、推荐架构

### 保持账户独立

```text
商城余额 -> user_extension
汽油账户 -> user_fuel_wallet(fuel_type=1)
柴油账户 -> user_fuel_wallet(fuel_type=2)
```

### 保持燃油独立账务链路

```text
user_fuel_recharge_order
user_fuel_wallet
user_fuel_wallet_log
```

### 统一业务规范

两类充值可以统一：

- 套餐字段和业务场景；
- 支付配置快照；
- 金额单位和金额校验；
- 订单状态规范；
- 支付成功幂等规则；
- 流水中的订单号、支付号、变更前后余额和变动金额；
- 前端分页、排序和金额展示。

但不要统一底层账户表和流水表。

## 七、实施建议

### 短期

不做大规模重构：

- 商城余额继续沿用现有历史链路；
- 汽油、柴油继续使用独立订单、钱包和流水；
- 补齐燃油退款、冲正、后台明细查询和对账能力；
- 验证数据库迁移脚本已经实际执行。

### 长期

如果需要统一架构，应抽象公共的充值业务规范，而不是强行合并底层账务表：

```text
统一支付订单规范
统一入账状态规范
统一流水字段规范
不同账户使用不同账户表和流水表
```

## 八、结论

```text
商城余额 = 用户商城账户 + MongoDB余额流水
燃油充值 = 独立油品钱包 + MySQL充值订单 + MySQL燃油流水
```

燃油不需要完全改成商城余额的实现。当前燃油独立账务设计更适合汽油、柴油账户，商城余额作为历史兼容实现保留即可。
