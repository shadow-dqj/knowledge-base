# 网络与防火墙

[[Ubuntu服务器/首页|← 运维中心]] · [[../03-运维手册/端口与依赖矩阵]]

## 网络边界

- 服务器 LAN IP：`192.168.1.117`。
- mall4cloud 对外端口均绑定此 IP，不绑定 `0.0.0.0`。
- Dify HTTP 只绑定 `192.168.1.117`；插件调试和 HTTPS 预留端口只绑定回环地址。
- New API 当前端口 3000 绑定所有 IPv4/IPv6 接口。
- 容器内部端口通过 `mall4cloud-network` 互联。
- PostgreSQL、Canal、Seata Console 等内部端口不发布到 LAN。

## UFW 实际状态

| 层面 | 状态 |
| --- | --- |
| `ufw.service` | active (exited)、enabled |
| `/etc/ufw/ufw.conf` | `ENABLED=no` |
| 规则实际生效 | 否 |

> [!warning] 不要只看 systemd
> `ufw.service=active` 不代表防火墙规则已启用；必须同时检查 `ufw.conf` 和 `ufw status verbose`。

## 检查

```bash
systemctl status ufw
grep -E '^(ENABLED|IPV6)=' /etc/ufw/ufw.conf
sudo ufw status verbose
ss -lntup
```

> [!danger] 启用前
> 必须预先放行 SSH、远程桌面、1Panel、MetaMCP、New API、Dify 和业务所需中间件端口，避免远程锁死。New API 当前绑定所有接口，启用公网路由或端口映射前应先收紧绑定或防火墙来源。
