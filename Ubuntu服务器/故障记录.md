## MongoDB 凭据不一致

### 现象

`mall4cloud-product` 创建 `MongoTemplate` 失败：

```text
Exception authenticating MongoCredential
mechanism=SCRAM-SHA-256
userName=mall4cloud
source=mall4cloud
```

同时出现 Tomcat WebappClassLoader 未停止 DNS 地址监听线程的警告。

### 根因

- MongoDB 容器健康，认证已开启。
- `mall4cloud` 用户存在于 `mall4cloud` 认证库，角色为 `dbOwner`，支持 SCRAM-SHA-1/SHA-256。
- 初始化脚本中的实际密码认证成功。
- Nacos 中 Product 使用的密码与实际初始化密码不一致，且本机没有环境变量覆盖。

DNS `Thread-26` 警告是 Spring ApplicationContext 启动失败后清理线程产生的次生现象，不是根因。

### 修复

通过 Nacos 配置 API 同步 MongoDB 客户端密码，未重置数据库用户：

- 8 个服务配置。
- 空 `tenant_id` 与 `public` 两套命名空间。
- 共 16 条记录。
- 仅修改 MongoDB password 字段。

验证结果：16/16 密码一致，8/8 配置对完全一致，MD5 异常 0，应用账号认证 `PASS`，MongoDB 和 Nacos 均健康。

修改前备份：

```text
/home/shadowdu/services/mall4cloud-middleware/backups/nacos/mall4cloud_nacos-before-mongodb-password-fix-20260813-125614.sql
```

备份权限为 `600`。

## Product 启动确认

修复后 `mall4cloud-product` 成功启动，并以 `192.168.1.100:9504` 注册到 Nacos，实例健康。

## Order Provider 未启动

### 现象

Product 的 XXL-Job `handleSkuStockChange` 调用 `PurchaseOrderFeignClient` 失败：

```text
No provider available
invokers: 0[]
validInvokers: 0[]
```

### 根因

- `mall4cloud-product` 已正常运行并健康注册。
- `mall4cloud-order` 没有运行。
- Nacos 中 `public-mall4cloud-order-dubbo-server` 实例数为 0。
- `PurchaseOrderFeignClient` mapping 和 Provider 元数据均不存在。
- 接口实现在 Order 服务的 `PurchaseOrderFeignController`。

因此这是实际的 Provider 缺失，不是 connectivity filter、Nacos 故障或 Mapping CAS。

### 恢复步骤

1. 启动 `mall4cloud-order`。
2. 确认 Nacos 出现 `public-mall4cloud-order-dubbo-server` 健康实例。
3. 确认 `PurchaseOrderFeignClient` mapping 和 Provider 元数据存在。
4. Product 通常无需重启，Dubbo 会动态发现新 Provider。
5. Order 就绪后重新执行 XXL-Job `handleSkuStockChange`。

### 库存游标风险

`SkuStockServiceImpl.handleSkuStockChange()` 在 `finally` 中无论成功失败都会更新 `SKU_CHANGE_STATISTICS_TIME`。本次远程调用失败后游标仍推进，下一次任务只回溯 15 秒，可能跳过失败窗口中更早的库存变化。

开发环境恢复建议：

- 数据量较小时，Order 就绪后执行一次 `intiStock` 做完整库存对齐。
- 数据量较大时，将游标恢复到失败前，再手动执行 `handleSkuStockChange`。
- 不要在未知数据量下直接删除游标触发全量扫描。

长期代码建议：仅在任务成功后推进游标，失败时保留旧值。
