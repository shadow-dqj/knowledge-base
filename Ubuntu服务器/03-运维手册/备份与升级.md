# 备份与升级

## 备份矩阵

| 数据 | 推荐方式 | 不能替代的原因 |
| --- | --- | --- |
| MySQL | `mysqldump --single-transaction` | 卷热复制可能不一致 |
| MongoDB | `mongodump` | 需数据库一致性视图 |
| MinIO | `mc mirror` / 服务级复制 | 对象元数据与并发写入 |
| Elasticsearch | Snapshot Repository 或确认可重建 | 直接复制数据目录不安全 |
| RocketMQ | 备份 Broker Store 并记录位点 | 消息与消费状态 |
| WuKongIM | 服务停写窗口或一致性方案 | 频道/消息数据持续写入 |
| Compose 配置 | `compose.yaml`、`.env`、`config/` | 重建服务所需 |
| MetaMCP | `update.sh` 自动备份 PostgreSQL | 应用状态位于数据库 |
| New API | `data/`、`logs/`、Compose 和 `.env` | SQLite 与应用配置位于绑定目录 |
| Dify | `volumes/`、`.env`、Compose 与 override | PostgreSQL、Redis、Weaviate 和上传文件均需保留 |

## 升级流程

1. 阅读兼容性和迁移说明。
2. 创建数据库/对象/配置备份。
3. 记录当前镜像摘要、版本和健康状态。
4. 校验 Compose：`docker compose config --quiet`。
5. 拉取固定版本镜像。
6. 分层重建，按 [[启停与恢复]] 验证依赖。
7. 执行 [[日常巡检]] 和业务冒烟测试。
8. 验证备份可读取，不只验证文件存在。

> [!warning] 固定版本
> mall4cloud 中间件不随意改用 `latest`。MetaMCP 和 New API 当前既有策略为
> `latest`；New API 在线更新命令见 [[Ubuntu服务器/02-平台服务/New API]]。
> Dify 组件版本必须跟随官方 Compose 兼容矩阵，不能单独改成不匹配的
> `latest`。

## 专项约束

- Elasticsearch 升级必须匹配 `analysis-ik`。
- Nacos 升级检查数据库表结构。
- Canal 重建记录 binlog 文件/位点。
- RocketMQ 升级备份 Broker Store。
- Dify 跨版本升级前保留 `.env`、`volumes/` 和
  `docker-compose.override.yaml`，阅读发布说明和数据库迁移要求。
- Dify `update-images.sh` 只刷新当前版本所引用镜像，不执行跨版本升级。
- 凭据变更同步 [[Ubuntu服务器/_敏感/中间件凭据清单]] 和客户端配置。
