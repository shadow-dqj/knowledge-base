## 凭据规则

默认情况下，普通运维笔记不保存：

- SSH 私钥内容或 SSH 密码。
- 1Panel 用户名、密码和实际安全入口。
- MetaMCP 管理凭据。
- Compose `.env` 完整内容。
- 诊断过程中产生的短期 Nacos access token 或动态 Dubbo Provider token。

经用户明确确认接受 Vault 同步到 GitHub/Gitee 及历史记录的风险后，mall4cloud 中间件的开发环境账号、密码和长期内部密钥集中保存在 [[中间件凭据清单]]，不分散复制到其他主题笔记。该例外不包含 1Panel、MetaMCP 或 SSH 私钥。

敏感文件的服务器位置：

| 文件 | 权限 | 用途 |
| --- | ---: | --- |
| `/home/shadowdu/.config/1panel/admin-credentials.txt` | `600` | 1Panel 完整凭据 |
| `/home/shadowdu/services/metamcp/.env` | `600` | MetaMCP 环境变量 |
| `/home/shadowdu/services/mall4cloud-middleware/.env` | `600` | mall4cloud 环境变量 |

修改凭据时应先更新服务器权威来源并验证服务认证，再维护 Obsidian 清单。

## 禁止操作

持久化 mall4cloud Compose 项目禁止执行：

```bash
docker compose down -v
```

其他禁止事项：

- 不删除 `/mnt/docker-data` 的 systemd 挂载保护。
- 不将 Docker `data-root` 改回 `/var/lib/docker`。
- 不清空 Redis 库存和缓存数据。
- 不重复导入已经执行的 20 份 MySQL 初始化 SQL。
- 不直接删除 `public-dubbo` mapping 或 Provider 元数据来消除告警。
- 不在未评估全部端口前直接启用 UFW。

## 备份建议

升级或结构调整前至少备份：

1. MySQL 全库逻辑备份。
2. MongoDB 业务库。
3. MinIO `mall4cloud` bucket。
4. Elasticsearch 索引，或确认可由权威数据源重建。
5. Compose 文件、`.env` 与 `config/`。
6. RocketMQ Broker Store。
7. WuKongIM 数据卷。

不要只复制正在写入的数据卷目录作为唯一备份，应优先使用数据库或服务自身的一致性备份工具。

## 升级检查

- 固定镜像版本，不随意改为 `latest`；MetaMCP 的既有策略除外。
- MySQL、MongoDB、Nacos、Seata 和 Elasticsearch 升级前检查迁移要求。
- Elasticsearch 与 `analysis-ik` 插件必须版本一致。
- Nacos 升级时检查表结构。
- Canal 重建后核对 binlog 文件和位点。
- 升级后验证两个 Compose 项目、Nacos、MongoDB 和对外端口。

## 动态令牌

诊断日志可能包含 Nacos JWT 或 Dubbo Provider 动态 token。不要将其复制到笔记；若 token 不是每次启动自动生成，应执行轮换。
